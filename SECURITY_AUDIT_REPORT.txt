──────────────────────────────────────────────────────────────────────────────

  const MAX_VMS_PER_USER = 10;
  if ((count || 0) >= MAX_VMS_PER_USER) {
    return Response.json({ ok: false, error: "VM limit reached" }, { status: 429 });
  }

──────────────────────────────────────────────────────────────────────────────
[HIGH-4] TOCTOU Race Condition in IP Allocation
──────────────────────────────────────────────────────────────────────────────
File: app/api/services/compute/vms/create/route.ts (lines 280-310)
Risk: IP allocation uses a check-then-use pattern:
      1. Query all used IPs
      2. Select an unused IP
      3. Insert server record with that IP
      
      Between steps 2 and 3, another request could reserve the same IP.
      The DB insert may succeed (no unique constraint enforced in code) 
      resulting in two VMs getting the same IP. The code does check for 
      duplicates before insert, but there's a race window.

Fix: Use a database-level unique constraint on servers.ip + status, 
or use SELECT ... FOR UPDATE / advisory locks, or use a dedicated 
IP allocation table with atomic claim semantics:
  UPDATE public_ip_pool_ips 
  SET claimed_by = $serverId, claimed_at = NOW()
  WHERE pool_id = $poolId AND ip = $ip AND claimed_by IS NULL

──────────────────────────────────────────────────────────────────────────────
File: app/api/services/compute/vms/power/route.ts (line ~80)
Risk: After sending a power action to Proxmox, the DB status is

──────────────────────────────────────────────────────────────────────────────

  SECTION 6: WHAT'S DONE WELL ✓
═══════════════════════════════════════════════════════════════════════════════

✓ Ownership Checks: All CRUD routes properly verify owner_id === user.id
  before allowing operations. Both filter-based (SELECT ... eq owner_id)
  and explicit checks are used.

✓ Hostname Validation: Strict regex validation 
  /^[a-zA-Z0-9]([a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?$/ prevents command 
  injection through hostnames passed to Proxmox/SSH. Applied consistently 
  in both user and admin routes.

✓ SSH Command Injection Prevention: proxmox-utils.ts validates IPs with 
  isValidIPv4() and bridge names with isValidBridgeName() before passing 
  them to SSH commands. This prevents shell injection in addHostRoute() 
  and removeHostRoute().

✓ VNC Token Design: HMAC-signed tokens with expiry, nonce for uniqueness,
  and constant-time comparison for signature verification. Good crypto 
  practices.

✓ Rate Limiting on Expensive Operations: Console (10/min) and metrics 
  (30/min) endpoints have per-user rate limits via Redis. Auth routes 
  have IP-based rate limiting in middleware.

✓ Metrics Sanitization: VM metrics data is properly sanitized — NaN,
  Infinity values are replaced with 0, percentages are clamped to 0-100.
  Prevents rendering issues and information leakage.

✓ Password Complexity: Strong validation for RDP passwords (12+ chars,
  3 of 4 complexity categories). Linux passwords require 12+ chars.

✓ Error Messages: User-facing errors are generic ("Unable to reach your 
  server") while technical details go to console.error. No stack traces 
  or internal details leaked to users.

✓ Smart Host Selection: Capacity-aware host selection with scoring
