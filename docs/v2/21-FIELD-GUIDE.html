Deploy v2 Field Guide

Where every piece of this platform physically lives, what each vendor is responsible for, how a request and a deploy actually travel through it, and where in the codebase to go when you need to change something. Written to be handed to somebody on their first day.

Edge
Cloudflare — public TLS, DNS, WAF, customer domains
Compute
Linode — the cluster's machines and every build VM
Orchestration
Kubernetes (LKE) — scheduling and routing inside the cluster
Control plane
Supabase Postgres — desired state, the source of truth
Storage
Cloudflare R2 — build logs, image tarballs, the registry

Those five colours recur throughout this document. Wherever you see one, it tells you which vendor owns the thing being described — which is the question you will keep asking for the first fortnight.

1 · What happens when someone visits an app

Top to bottom, this is the whole request path. Nothing else is in it.

Cloudflare
ahurasense.com — proxied DNS Terminates public TLS. One Origin CA certificate covers *.ahurasense.com and is valid to 2041. Customer domains ride on Cloudflare for SaaS custom hostnames. WAF and rate limiting sit here, not in our code.
│ proxied A record → origin
Linode
NodeBalancer 2437817 · 172.236.185.23 The only public entry point to the cluster. Firewall 143239782 is attached to it and permits Cloudflare's IP ranges only — a direct connection to that address times out.
│
Kubernetes
traefik · ahura-system Reads one Ingress per alias. An alias is a row in paas.aliases mapping a hostname to a specific deployment, which is why promote and rollback are a database write rather than a rebuild.
│
Kubernetes
the app's pod · app-prj-<ref> One namespace per project. The pod runs under the gvisor RuntimeClass with all capabilities dropped, no service-account token, and a NetworkPolicy that only lets the gateway reach it.

If the app is asleep

Scale-to-zero is opt-in and currently on for one project. When it is on and the pod is down, the request is held by the activator in ahura-system, which wakes the app and proxies once it is ready. The visitor waits a few seconds rather than seeing a 503 — that is the difference between "asleep" and "down", and it is the whole reason the feature is safe to enable.

Postgres is the source of truth, not Kubernetes

This is the single most important idea in the system. Postgres holds every app; Kubernetes holds only the warm ones. The reconciler reads desired state from Postgres and converges the cluster toward it — it is level-triggered, so it works from whatever the cluster currently is, and it is the only writer to Kubernetes. Nothing else runs kubectl.

The practical consequence for you: to change what is running, change a row. Do not patch the cluster by hand — the next reconcile will undo it, and you will have spent an afternoon learning that.

4 · What happens when someone deploys

Nine stages. deployFromRepo in lib/paas/deploy.ts runs all of them and reports each by name — those names are what you see in the build output and in the UI.

StageOwnerWhat it does
detectreadAsk the git provider for the default branch, list the root directory in one call, read only the marker files that exist. Produces a framework, runtime, build command, output directory and port.
projectSupabaseFind or create the project row, scoped to the caller's team.
deploymentSupabaseAn immutable row keyed (environment, sha). A trigger refuses updates to the fields that identify a build.
buildLinodeLease one throwaway VM, run rootless BuildKit, stream the log to R2, destroy the VM on every exit path including a throw.
publishK8sAn in-cluster Job pulls the tarball from R2 and pushes it into the registry. From here the image is addressed by digest.
reclaimR2Delete the tarball — but only after confirming the registry holds both the manifest blob and the repository link.
routeSupabaseCreate or reuse the alias row. Aliases are scoped by environment, so a preview cannot repoint production.
convergeK8sThe reconciler writes Deployment, Service, NetworkPolicy and one Ingress per alias.
dnsCloudflareUpsert the proxied record.

The build VM — read this before you change anything in it

v1's build agent held the cluster kubeconfig and the platform-wide webhook secret, which is how a branch name became full cluster compromise. v2's VM is designed around the inverse question: what is the worst an attacker who fully owns this machine can do?

It holdsIt does not hold
The tenant's source · a short-lived git credential scoped to one repository, in a 0600 file deleted after the clone · three presigned R2 URLs, one key each · build secrets via --mount=type=secret, which never enters a layer Any kubeconfig · any registry push credential · any route to any cluster · any other tenant's cache, source or secret · any long-lived platform credential at all

A rule enforced in code, not by convention

build/vm.ts refuses at render time to emit a clone URL shaped https://user:token@host/…. Git echoes the remote URL in its own error output, and that output is teed into a log served to team members. The credential goes in a separate file, and the host for that file is derived from the clone URL so the two cannot disagree.

Why most of them only look

A sweep that reports is safe to run wrong. A sweep that acts is not. Only two write — meter-apps and project-teardown — and teardown was enabled first and allowed to converge to zero before metering was switched on, because billing an app whose pods were never removed is exactly v1's defect.

The one that is not like the others

V2_ENV_MASTER_KEY is the root of the key derivation for every customer's environment variables and every stored OAuth token. Lose it and every secret in the database is unreadable; leak it and every secret is readable. It is not in any repo, and it must not be pasted into a chat, a ticket or a terminal you did not open yourself.

node --experimental-strip-types --env-file-if-exists=.env.local \

8 · House rules

Each of these exists because it was learned the hard way. They will save you the same day they cost somebody else.

Change a row, not the clusterThe reconciler is the only writer to Kubernetes. A hand-patched Deployment is undone on the next converge.
Empty ≠ unknownThe most repeated bug in this project. A 404 means absent; a 429 or a 500 means we could not ask. Conflating them told customers to add a package.json they already had. Null is absent; unknown throws.
Skip is not passTests that need the live database skip when it is unreachable. Skip means "could not check". A suite that turns that into a pass is asserting nothing.
Verify by runningNot by reading, and not through a pipe — a piped command reports the pipeline's exit code, not the script's. That has produced a clean-looking sweep that never ran a single repository.
Prove a guard by breaking itRemove it and the test must fail. Otherwise "no violations found" and "cannot detect violations" look identical.
Customers never see our vendorsOnly a CustomerError keeps its text; everything else becomes a generic message plus a reference, with the detail logged. An enforcement test scans for this — see lib/paas/errors.ts.
Never break v1It shares the database. v2 lives in the paas schema and touches nothing in public or billing.
Do not leave apps runningTest apps are deleted after each run. An accumulating fleet bills, and it hides the next failure in noise.

Two facts about this repo that will confuse you on day one

The test command is not npm test. That is vitest, scoped to tests/**, and it runs v1's integration suite — which fails without a live database. The v2 suite is npm run test:paas, on Node's own runner, and it needs nothing.

Scripts run under node --experimental-strip-types, not tsx. tsx cannot compile a top-level await to CommonJS and dies in the transform — which once looked exactly like a clean run.
